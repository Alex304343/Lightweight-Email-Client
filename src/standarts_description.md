Ниже приведено академическое резюме стандартов **TCP-сокетов**, а также протоколов прикладного уровня **SMTP** и **POP3**.

---

### 1. TCP-сокеты (Transmission Control Protocol / Transport Layer)

TCP — это базовый транспортный протокол (описанный в **RFC 793**), который обеспечивает надежную, упорядоченную и гарантированную доставку данных между двумя узлами в сети.

*   **Концепция потока байтов (Byte Stream):** TCP не знает границ сообщений. Для него данные — это непрерывный поток воды (байт). Если отправитель запишет в сокет 100 байт, а затем еще 50, получатель может прочитать их как единый блок в 150 байт, либо пять раз по 30 байт. Организация границ сообщений (например, добавление разделителей вроде `\r\n`) — задача протоколов верхнего уровня.
*   **Установление соединения (3-way handshake):** Перед передачей данных TCP выполняет "рукопожатие": клиент отправляет пакет `SYN`, сервер отвечает `SYN-ACK`, клиент подтверждает `ACK`. Только после этого канал считается открытым.
*   **Сокет (Socket):** Это программный интерфейс (API, стандарт POSIX в Unix-системах), абстрагирующий конечную точку сетевого соединения. Сокет идентифицируется связкой: `IP-адрес + Порт`.
*   **Надежность:** TCP контролирует порядок пакетов, заменяет утерянные пакеты (пересдача) и управляет скоростью потока, снимая эту головную боль с разработчика прикладных программ.

### 2. SMTP (Simple Mail Transfer Protocol / Application Layer)

SMTP — это стандартный протокол для **отправки и пересылки** электронной почты (описан в **RFC 5321**).

*   **Архитектура "Клиент-Сервер":** Протокол работает по модели запрос-ответ на базе TCP (обычно стандартный порт — 25, для защищенных соединений — 465 или 587).
*   **Текстовый характер:** Все команды клиента и ответы сервера представляют собой читаемый текст в кодировке ASCII, разделенный символами конца строки `<CRLF>` (`\r\n`).
*   **Числовые коды ответа:** Как и HTTP, SMTP возвращает трехзначные коды состояния:
    *   `2xx` — Успех (например, `250 OK`).
    *   `3xx` — Промежуточный успех, требуется продолжение (например, `354 Start mail input`).
    *   `4xx / 5xx` — Ошибки (временные или постоянные).
*   **Жизненный цикл сессии (Конвейер команд):**
    1.  **Соединение:** Сервер шлет приветствие (`220`).
    2.  **Идентификация:** Клиент здоровается (`HELO` или `EHLO`).
    3.  **Конверт (Envelope):**
        *   `MAIL FROM:<адрес>` — указывает источник (кто платит за доставку / куда слать отлупы).
        *   `RCPT TO:<адрес>` — указывает получателя (может повторяться для рассылки одному или нескольким адресатам).
    4.  **Данные (`DATA`):** Клиент передает тело транзакции. Сюда входят заголовки (`Subject:`, `From:`, `To:`) и само тело письма.
    5.  **Конец передачи:** Блок данных всегда завершается уникальной последовательностью — **одиночной точкой на пустой строке** (`\r\n.\r\n`).
    6.  **Завершение:** Команда `QUIT` закрывает сессию.
*   **Особенность (Dot-stuffing):** Если в самом тексте письма строка начинается с точки, стандарт обязывает клиента удваивать её (`..`), чтобы сервер не принял её за конец сообщения.

### 3. POP3 (Post Office Protocol - Version 3 / Application Layer)

POP3 — это протокол для **получения** почты с удаленного сервера (описан в **RFC 1939**). Его главная концепция — "скачай и удали" (хотя современные клиенты умеют оставлять копии). Работает по TCP (стандартный порт — 110, защищенный — 995).

*   **Текстовый протокол с префиксами статуса:** В отличие от числовых кодов SMTP, POP3 отвечает на каждую команду текстовыми маркерами:
    *   `+OK` — операция выполнена успешно.
    *   `-ERR` — произошла ошибка.
*   **Конечный автомат состояний (3 фазы сессии):**
    1.  **Авторизация (Authorization State):**
        *   Клиент подключается, сервер шлет `+OK`.
        *   Клиент передает имя пользователя: `USER <имя>`.
        *   Клиент передает пароль: `PASS <пароль>`.
        *   После успеха сервер переходит в рабочее состояние.
    2.  **Транзакция (Transaction State):**
        *   `STAT` — запрашивает количество писем и их общий размер (сервер отвечает, например, `+OK 2 3200`).
        *   `LIST` — запрашивает список всех писем с их номерами и размерами.
        *   `RETR <номер>` — запрашивает скачивание конкретного письма.
        *   `DELE <номер>` — помечает письмо как удаленное (удаление произойдет позже).
    3.  **Обновление (Update State):**
        *   Вызывается командой `QUIT`. Сервер физически удаляет все письма, помеченные как `DELE`, и закрывает TCP-соединение.
*   **Многострочные ответы:** При запросах вроде `LIST` или `RETR` сервер сначала возвращает строку с `+OK`, а затем шлет поток данных тела сообщения. Конец многострочного ответа, как и в SMTP, обозначается символами `\r\n.\r\n` (точка на отдельной строке).
